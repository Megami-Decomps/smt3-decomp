# Non-matching drafts: code_0029B780

Conventions and the reason these are kept: [../nonmatching.md](../nonmatching.md).

## pipeMakeNodeLink (code_0029B780, 0x80)

7 of 32 words differ, at the exact 128-byte size, with every instruction the same.

Three registers are permuted. Retail puts the biased `&pInfo->nextId` in `$4`,
the loop bound hoisted out of `pInfo->maxNum` in `$6`, and the id read through
that pointer in `$3`; the draft swaps the first two and puts the id in `$4`,
which also swaps the `sh` and the `addiu` that follow it. The pointer pseudo
is created inside the `if` arm here, so it is numbered after the bound.
Someone attacking this needs the pointer pseudo created before the bound
without also moving its `addiu` out of the loop preheader.

Ruled out: the pointer declared at the top of the function or second after the
node (11 words and over-long respectively); the bound read into a local
instead of left for gcc to hoist out of `pInfo->maxNum` (16); no pointer local
at all, which reads `nextId` twice, once `lw` and once `lhu` (11); and all 24
orders of the four stores in the arm.

The former `code_0029B780` aggregate covered eleven original translation units
of pipe-minigame and config code. Recurring measured patterns include a `u32`
switch index, which changes which case gcc tests first, and
`for (i = n; i != -1; i--)` for table scans, where `i >= 0` gives `bgezl`
against retail's `bnel` against a materialised `-1`. Local resets used to
preserve a final `jal` require the qualified evidence in the
[matching policy](../CONTRIBUTING.md#matching-rules).


## dds3DrawConfigText (code_0029B780, 0x244)

41 of 145 words differ at the exact 580-byte size, first at +0x50. The
seven signed arguments are x, y, depth, option count, row index, value and
ordering-table index. The row is selected when its index equals the signed
cursor base at GBWK+0x3E plus the unsigned cursor offset at +0x40.

Value drawing always runs; bar drawing additionally requires row < 3 and a
nonnegative value. The four corner colors use the independently retrieved
fade alpha. Rows below 3 draw option fills, a label and three cap sprites,
including when the option count is nonpositive. The sprite table is the real
eight-byte resource/entry pointer pair used by the drawing providers.

The repeated drawing body and loop match from +0xF8 onward. The residual is
argument setup before value drawing, color-store scheduling and the loop
preheader: retail reloads the row directly into the call argument register,
while this computes selection through a temporary and adds a move. Native
also retains one loop-entry nop that this source lacks. Computing the range
flag before selection, assigning selection in the call, and declaring value
drawing with its actual integer return type do not close it. Explicit corner
stores make their order inspectable; no artificial use or pinned register is
needed to retain this reconstruction. Production remains assembly-backed.


## dds3DrawConfigPanel (code_0029B780, 0x258)

145 of 150 instruction words match at the native 600-byte size. The five
remaining words are the first panel-sprite call's argument scheduling and
the register choices for the subsequent work-pointer and texture-handle loads.
The texture check follows the sprite callback; each configuration-flag query
reads the live global table after preceding drawing calls. The four text rows,
six sprites, fade-alpha read and final item call preserve native arguments and
ordering. Production retains the assembly fallback.

Naming the work pointer or texture handle in a separate local does not change
the residual. No artificial dependency or altered provider contract is used.
